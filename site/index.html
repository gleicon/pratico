Docker for Apple silicon Macs

Every container in its own small VM.

A Docker daemon and a menubar app. No shared Linux VM, no Docker Desktop. docker, Compose, and anything that speaks the Docker socket keep working.

Three steps

Nothing else to install: the app carries its own Linux kernel and init.

  1. Download and open it once

    Get Pratico-<version>.dmg from Releases and drag Pratico.app to Applications. The build is not yet notarized, so approve it once: Open Anyway in System Settings › Privacy & Security, or:

    xattr -dr com.apple.quarantine /Applications/Pratico.app

  2. Start the daemon from the menubar

    It serves the Docker API on ~/.pratico/docker.sock and starts at login. No password, no root: pratico never asks for one.

  3. Point docker at it, once

    A Docker context, which the CLI and Compose remember:

    docker context create pratico --docker host=unix://$HOME/.pratico/docker.sock
docker context use pratico

    Or export DOCKER_HOST=unix://$HOME/.pratico/docker.sock in ~/.zshrc. Tools that only know /var/run/docker.sock: the menubar explains the one sudo ln it takes.

What you get

The Docker you know, with the Mac's own tools around it, and nothing downgraded to fit a checklist.

One VM per container

Each container boots its own lightweight VM on Apple's Virtualization.framework. A crash, a kernel panic, or a breakout stays in its box.

The Docker API, for real

run, exec -it, logs -f, cp, stats, healthchecks, networks with DNS, published ports, volumes, save and load, events. Docker CLI 25 to current.

A menubar that tells you things

Running containers with CPU, memory, health, and ports; open, stop, restart. Alerts when a port is reachable from other machines or a container turns unhealthy.

Disk use you can trust

Allocated blocks, shared layers counted once, slices that add up. Cleanup lists exactly what it removes and asks first; running work is never touched.

Images scanned for you

osv-scanner, grype, trivy, your own scanners, and CISA's exploited list. Malware or exploited CVEs stop and block the image; the menubar says why.

Snapshots in plain JSON

Every container, network, and volume definition in one .tar.gz you can read with an editor. Restore shows what each container could reach before it asks.

How it runs

Pratico is built on apple/containerization. The daemon speaks the Docker Engine API on a Unix socket; each container gets a small VM with its own kernel, started by a per-container shim so containers and their exit codes survive a daemon restart.

Networking is pratico-net, a user-space switch in Swift: isolated networks, DNS by name, the internet and the Mac (host.docker.internal), published ports, and connect or disconnect of running containers, cut at the switch.

Design notes: docs/design/runtime.md.

  1. docker CLI, Compose, Testcontainerstalk to ~/.pratico/docker.sock
  2. pratico-daemonthe Docker API, images, networks, volumes, scans
  3. pratico-shim, one per containerowns its VM on Virtualization.framework
  4. Linux VMa guest agent for exec, cp, stats, healthchecks
  5. your processstarted once its ports are bound and it reads as running

Scanning, your way

Every pulled image is scanned in the background and again daily with every scanner pratico finds. The menubar's shield only changes for what matters: critical or high findings, malware, or a CVE that is being exploited.

Bring your own scanner: any executable run as <path> <image.tar> that prints findings as JSON joins the others, and Scan Results shows which scanner found what.
