Your local container manager.

Pratico works with the tools you already use and gives you a new way to work with containers on your Mac: every workload isolated in its own virtual machine, every image checked before it can hurt you.

Download for macOS View source

Apple silicon · macOS 26 · Free and open source (MIT)

Compatible

Keep your tools

docker, Compose, and anything else that speaks the Docker API connect to pratico and keep working as before.

Isolated

One VM per workload

Every container boots its own small virtual machine. What happens in one stays there: no shared kernel, no shared Linux VM.

Protected

Images checked for you

Open source scanners inspect every image you pull. Malware and actively exploited flaws are stopped before they run.

Compatible with older tools

The Docker API, so nothing has to change

Pratico serves the Docker Engine API on a socket in your home folder. Point your tools at it once and use them as you always have.

$ docker context use pratico
$ docker run --rm alpine echo hello
hello
$ docker compose up -d
$ docker exec -it web sh
$ docker logs -f web

Docker CLI 25 to current

Version negotiation as Docker Engine does it; older clients get Docker's own message.

Everyday commands

run, exec -it, logs -f, cp, stats, healthchecks, events, save and load.

Networks and volumes

Isolated networks with DNS by name, published ports, named and anonymous volumes, tmpfs.

The socket inside containers

Mount docker.sock into a container, as CI tools and test frameworks do, and it reaches pratico.

A new way to work

Each workload in its own virtual machine

Most Mac setups run one Linux VM with every container inside it. Pratico, built on Apple's open source containerization framework, boots a small VM per container instead.

Contained failures

A kernel panic, a runaway process, or a breakout attempt stays inside one VM, away from your other workloads.

Light enough to use

About 400 ms from docker run to running, and about 200 MB of memory per idle container.

Visible from the menubar

What runs, with CPU, memory, health, and ports. Alerts when a port is open to your network or a container turns unhealthy.

Nothing else to install

The app carries its own Linux kernel. No root, no password, no Docker Desktop.

Protect yourself

Every image scanned with open source tools

When you pull an image, pratico runs every scanner it finds on your Mac against it, and again every day, because new flaws are published all the time. Their findings are merged, and each one says which scanner reported it.

  • osv-scanner

    Google · Apache 2.0

    Checks every package against OSV.dev, the open vulnerability database, malicious package reports included.

  • grype

    Anchore · Apache 2.0

    Matches the image's packages against its own vulnerability database, downloaded to your Mac.

  • trivy

    Aqua Security · Apache 2.0

    A second, independent database and package detection, so one scanner's blind spot is not yours.

  • CISA KEV

    U.S. CISA · public catalog

    Flags the vulnerabilities attackers exploit today, so the urgent ones stand out from the rest.

What happens with the results

  • Malware or an exploited flaw. The image is blocked, its containers stop, and a notification says why. You can allow an image you trust.
  • Critical or high findings. The menubar shield changes, and Scan Results lists them with the versions that fix them.
  • Medium and low. Listed, never in your way. You choose what blocks in Settings.

The Scanners menu gives the one Homebrew command that installs them. grype and trivy match on your Mac; osv-scanner sends package names and versions to the OSV.dev API. Image contents never leave your Mac.

Bring your own scanner

Any program that reads an image archive and prints findings as JSON joins the others, in Scan Results and in what blocks.

{"findings": [
  {"id": "CVE-2024-0001",
   "package": "openssl", "version": "3.0.1",
   "severity": "high", "fixed": ["3.0.2"]},
  {"id": "MAL-ACME-7",
   "package": "evil-pkg", "version": "6.6.6",
   "severity": "critical", "malicious": true}
]}

Get started

Install in three steps

  1. 1. Download and open

    Get the latest release and drag Pratico to Applications. The build is not notarized yet: approve it once with Open Anyway in System Settings › Privacy & Security, or run:

    xattr -dr com.apple.quarantine /Applications/Pratico.app

  2. 2. Start it from the menubar

    The daemon listens on ~/.pratico/docker.sock and starts at login.

  3. 3. Point your tools at it

    docker context create pratico --docker host=unix://$HOME/.pratico/docker.sock
docker context use pratico

    Or set DOCKER_HOST=unix://$HOME/.pratico/docker.sock. Still to come: docker build and a notarized build; see the roadmap.
