# settled

- No paid Apple Developer Program account (2026-11-08). Ad-hoc signing only; Developer ID signing + notarization are optional `make dmg` paths used only when an identity is configured. See `SPEC.md` D-10.
- No restricted entitlements (e.g. `com.apple.vm.networking`): macOS kills binaries carrying them without a provisioning profile, and user approval cannot override that. Networking must work without them. See `SPEC.md` D-11.
- Users approve downloaded builds through Gatekeeper ("Open Anyway" or `xattr -dr com.apple.quarantine`); the app cannot prompt for this itself because Gatekeeper blocks before any code runs. A helper script inside the DMG does not help: it is quarantined too.
- Built via Makefiles and shipped as a `.dmg` with a background and Finder layout (`scripts/dmg.sh`); releases are plain `x.y.z` (`scripts/release.sh`), current 0.2.26.
- No pratico CLI (SPEC D-12). Pratico is a Mac app: menubar item, config window, listeners. `docker` is the CLI. Daemon control lives in the menubar.
- Listeners run in `pratico-daemon`, a background helper bundled in `Pratico.app` and started by a launch agent the menubar writes to `~/Library/LaunchAgents` (SPEC D-13).
- Users must not need Apple's `container` installed (2026-11-09). The embedded runtime (SPEC D-26, `docs/design/runtime.md`) replaced the CLI backend, removed 2026-11-12; limitations of the CLI are bugs to remove, not documented behavior.
- Behave like Docker by default and go beyond it where that helps (agents especially); never ship a weaker approximation because an acceptance criterion is literally met.
- Embedded networking is pure Swift with no extra binaries (SPEC D-27). Kernel and `vminit` are bundled, not downloaded by users.
- pratico runs no shell and no external program (2026-11-12): native Swift and system APIs only (tar through ContainerizationArchive, daemon start by `posix_spawn` of its own binary, stop by SIGTERM). Spawning pratico's own binaries (`pratico-daemon`, `pratico-shim`) is fine. Scanners are the exception: external tools by design (SPEC D-24), checked by the menubar's Scanners menu.
- Every removal the user can trigger asks first (cleanup, logins, alerts).
- Local Mac development first; production-only features stay out (2026-11-20). Won't do: TLS inspection and its CA, BPF LSM file audit and prevention, seccomp `user_notif`, `perf_event` profiling, zero-setup `docker build`, volume backup, IPv6, a local registry (`.project/roadmap.md`, Won't do). Remote Linux hosts are a later direction with fixed lines: KVM required, SSH only, the menubar sees every host, docker contexts act, no proxy and no CLI.

# hazards

- `pratico-shim` needs `com.apple.security.virtualization`. A plain `swift build` drops it; use `make build`, which re-signs. Symptom: `exit.json` says the process lacks the entitlement, exit 127.
- Shim sockets live in `<home>/run/<short id>.sock`; anything under `containers/<64-hex id>/` exceeds the 104-byte Unix socket limit.
- The MCP token (`~/.pratico/mcp-token`) is as powerful as `docker.sock`: never log it, never serve MCP beyond 127.0.0.1, and keep the Host/Origin checks before the token check (`MCPServer.refusal`).
- `make release` checks the tree is clean at its start, then runs tests and builds the DMG from the working tree minutes later: do not edit sources or build while it runs (twice, edits made during a release nearly went into its DMG).
- Container output reaches the daemon through `LogWatch` (kqueue on the shim's log, reopened after rotation, plus a 1 s tick). Do not go back to a polling thread per container: it cost 2.6% of a core with 16 idle containers (0.5% now).
- Invariants are `precondition`s (Tiger Style): a broken one stops the process, the daemon or that container's shim. Input from clients or from a container (`ps` output, guest files) is never asserted; it is answered with an APIError: a precondition there lets a client or an image crash the daemon.
- `blocking { }` (ImageBackend.swift) waits on a semaphore; call it only from the daemon's connection threads or plain threads, never from a Swift concurrency context.
- Swift `case A, B where cond:` applies `where` to `B` only. A route written that way matched `A` unconditionally and sent no response, hanging `docker cp`.
- `make probe` and an embedded daemon without `--home` use `~/.pratico`, which the installed app also uses. Test with a temporary `--home`.
- Virtualization.framework allows 4 network devices per VM (`VZErrorDomain Code=2 "The number of network devices is greater than the maximum number supported"`). Since D-43 a VM has one card with an address per network; `ShimNIC.slots` (4) only describes VMs started before that, which still run with a card per network until restarted.
- On a shared card the switch tells networks apart by source address only (`NetSwitch.endpoint`). Anything that delivers or accepts a frame for a VM must go through that classification, or a disconnected address on the card would pass traffic. Delivery (`NetSwitch.forward`) also filters by destination address, not MAC alone: a shared card answers for every network's address (e2e: raw frame via `e2e/frame.py`).
- `NetPort.mac` is what the network sees and `NetPort.card` what the guest has (D-44). Spoof checks compare against `card`; anything the switch sends to a VM must go through `NetSwitch.send`, which rewrites `mac` back to `card`, or the guest drops it.
- vminitd has no route delete: moving the default route means `down`/`up` on the link, then `routeAddDefault`, then `configureDNS` (Shim `nic(.route)`). `routeAddDefault` alone fails with EEXIST.
- `spec.json`'s `nics` is a `NICSlots` object (`slots`, `primary`). `NICSlots.init(from:)` still reads the older plain array, and its per-NIC `primary` flag, for VMs started by an older daemon; keep it while such VMs may still run.
- The shim's `GuestAddresses`, not the daemon, records which addresses each guest card holds: the shim outlives daemon restarts, and vminitd's `addressAdd` (netlink `NLM_F_EXCL`) fails on a duplicate without an errno the daemon can see.
- vminitd has no address or route delete RPC: a hot-disconnected address stays on the card (on a down link for pre-D-43 VMs). The switch, not the guest, is what cuts traffic; keep every delivery path behind its port registry (`NetSwitch.deliver`).
- `SSL_CERT_FILE` replaces the daemon registry client's trust roots (Docker Hub stops verifying). macOS rejects a self-signed CA cert used directly as a TLS server cert; test registries need a CA plus a leaf.
- Never run pratico code as root from `Pratico.app`: the bundle is the user's (drag install), `/Applications` is group-writable by `admin`, and ad-hoc signing gives launchd nothing to verify, so a root job with `BundleProgram` is a user-to-root escalation. For `/var/run/docker.sock` (D-30) pratico only shows `sudo` commands; the user runs them (2026-11-12: keep it simple, no admin prompt from the app).
- The daemon refuses to start while another answers on its socket (`DaemonError.alreadyServing`, no `daemon.err` written); it used to unlink the socket and take over. The menubar spawns it (own session, reaped by `waitpid`), and launchd starts it at login from `~/Library/LaunchAgents/dev.pratico.daemon.plist`.
- Do not go back to `SMAppService` for the daemon while builds are ad-hoc signed: its Background Task Management record pins the daemon's code signature, and after a rebuild, a move, or an update launchd refuses it (`OS_REASON_CODESIGNING | Launch Constraint Violation`, job `spawn failed`, `needs LWCR update`). The menubar just showed "starting…" forever. `LaunchAgent.start()` still unregisters an old SMAppService registration of the same label.
- The daemon closes a connection after the reply when the request says `Connection: close`; it used to keep it open, so `DaemonProbe` (which also stops at `Content-Length` now) waited out its timeout on every call.
- SwiftUI lists and tables need unique row IDs: keyed by a scan advisory alone, Scan Results repeated rows (one advisory, several packages).
- `bash` reads scripts while running: never edit `e2e/*.sh` during a run.
- In e2e scripts, never use a bare `wait`: the suites leave `docker events` watchers running in the background, so `wait` never returns. Wait on the PIDs you started.
- Docker `label` filters are AND-ed (`Filters.pass`); other keys OR their values. `compose exec` finds its container with two label filters, so OR-ing them runs commands in another service.
- Concurrent creates race unless one critical section covers check and insert: network create is serialized (subnet choice), container names are reserved until the record exists.
- The guest kernel and init are pratico's own builds (D-52, D-53), pinned by `vm/kernel/vmlinux.sha256` and `vm/init/vminit.sha256`; `e2e/embedded.sh` reads the expected `uname -r` from `scripts/build-kernel.sh`. Any change under `Vendor/containerization` that vminitd or vmexec links changes the init image: rebuild with `REPRO=1 UPDATE=1 scripts/build-init.sh .cache/init/out`, then `make assets`.
- The flight recorder's record (`struct pratico_event`) is defined in `vm/bpf/recorder.h` and read at the same offsets by `Activity.Layout` (host) and `Recorder.Layout` (vminitd): change all three together; the e2e recorder checks catch a mismatch.
- The shim writes `exit.json` only after the recorder's stream ends (D-57): readers of a finished container's activity rely on that order; keep the drain waits bounded (`ActivityReader.drainTimeout`).
- Code under `Vendor/containerization` follows its lint rules (`NeverForceUnwrap`, `NeverUseForceTry`) and carries an Apache-2.0 header naming who changed or added it (`Vendor/README.md` lists every change).
- `FileHandle.read(upToCount:)` on a socket waits for the whole count; read streams with `read(2)` (`ShimHost.recordActivity`).
- Never clean up the installed pratico (`~/.pratico`) with broad commands such as `docker ps -q | xargs docker rm -f`: they take the user's containers too. Remove test containers by name.
- Real Compose is `/opt/homebrew/bin/docker-compose` (5.x) or the `docker compose` plugin via `cliPluginsExtraDirs`; older Compose builds (API 1.41) are refused like dockerd refuses them.
